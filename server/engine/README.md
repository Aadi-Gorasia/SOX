# SOX search engine v3

The engine analyzes Ultimate Tic-Tac-Toe using flattened moves
`sector * 9 + cell`. It shares legal routing, draws, and reversible move handling
with hints, game reviews, and puzzles. X starts; a finished destination sector
allows the next player to choose any open sector.

## Search

- Iterative deepening with principal-variation search and alpha-beta pruning.
- A bounded transposition table includes occupancy, sector results, forced board,
  and side to move. Entries carry exact/lower/upper bounds and mate-distance scores.
- Move ordering prioritizes the previous best line, macro-relevant captures,
  threats, killer moves, and cutoff history.
- Up to two additional tactical plies at unstable leaves, examining **all legal
  replies**. There is no stand-pat, capture-only quiescence, or null-move pruning:
  passing and ignoring quiet routing moves are unsound here.
- Exact root symmetry reduction skips equivalent rotated/reflected positions.
  A blocked macro board is recognized as a proven draw even before all sectors close.
- Cached local-board geometry, distinct threat squares, macro-sector importance,
  and side-to-move routing bonuses inform evaluation. Giving an opponent free
  choice is no longer rewarded.
- Hints use focused root search (200,000 nodes / 1.5 seconds). Other root moves
  may have upper bounds and are labelled accordingly. Reviews and puzzles use
  full-window root searches so move-regret comparisons use comparable scores.
- Defaults: up to 16 plies; reviews 30,000 nodes / 500 ms per position; training
  10,000–120,000 nodes / 1 second depending on difficulty. These are budgets,
  not calibrated Elo playing strengths.

Only completed iterations replace the result. If none finishes, the engine
returns a legal static fallback with `analysisComplete: false`; it does not
label every move as equally good. `principalVariation`, `searchDepth`,
`nodesSearched`, `analysisTimeMs`, `solved`, and signed `mateInPlies` expose what
was actually found. PVs may be shorter than depth when an exact table continuation
is unavailable. Positive mate distance means a win for the side to move;
negative means a forced loss. Scores are engine units, not chess centipawns.

`solved` means a terminal win/loss was proved or the entire remaining endgame
was searched. Other recommendations are the best line found within the budget,
not a claim that Ultimate Tic-Tac-Toe is solved. No opening book or learned
network is included.

## Server integration

`asyncSearch.js` owns two lazy worker threads with at most 32 waiting jobs.
Workers are unreferenced while idle; searches have node/time bounds plus a
12-second worker watchdog. Analysis does not block Socket.IO on the main thread.
Overloaded queues fail rather than growing without limit. A full review may take
up to about 41 seconds of search work, plus queuing, for an 81-move record.

The review schema persists the principal variation, depth and proof status.
`reviewSummary.engineVersion` invalidates reviews generated by the old engine.
The client shows search depth, the best line, and whether the outcome is proven.

## Verification

Run `npm test --prefix server` from the repository root. Tests cover rule
restoration, forced routing, winning tactics, PVS/TT agreement with unpruned
minimax, 16 seeded small endgames solved exhaustively, interrupted searches,
worker queue limits, event-loop responsiveness, and review persistence.

A small paired match against the preceding engine (`48d9def`), seed 92831,
six eight-ply openings, each played with colours swapped, at 5,000 nodes per
move gave v2 **8 wins, 1 draw, 3 losses**. V2 searched 4.56 nominal plies plus tactical extensions on average; baseline
5.10 nominal plies. In a symmetric opening fixture, symmetry reduction cut the
work from 1,492 to 376 nodes at identical depth and score. This is a smoke benchmark, not an Elo estimate or a broad strength claim.

To reproduce, extract the old `server/engine` directory from commit `48d9def`
into a separate temporary directory, then run:

```
node server/engine/benchmark.js /path/to/baseline/server/engine
```

The benchmark uses legal moves, identical starting positions, swapped colours,
and the same node cap. Timing will vary across hardware. The source rules are
unchanged; future work should expand independent rule and adversarial corpora,
measure equal-time matches, and tune evaluation on held-out games before claiming
further strength gains.

## Computer opponents and coaching

Six presets and a custom 400–2600 difficulty slider adjust search budgets and move selection. These labels are approximate, not calibrated Elo ratings. Computer games are saved, resumable, and unrated; the API validates ownership, legal moves, and expected move count before atomic updates.

Review advantage is the searched score relative to X, not a win probability or player Elo. Coaching is generated from engine evidence for the selected player, with links to relevant moves. Great and Brilliant require forced-result evidence; ordinary captures do not automatically earn these grades. Incomplete searches are labelled unavailable rather than graded as optimal.
